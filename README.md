# WeDesign — запуск

Терминал не нужен. Всё делается мышью: файлы в GitHub, переменные в Vercel.

## 1. Залейте файлы в репозиторий

Структура должна быть ровно такой:

```
index.html                 главная: сборка, оплата, продление
admin.html                 ваша панель
oferta.html                договор
politika.html              обработка данных
fayl.html                  инструкция клиенту, как разместить файл самому
robots.txt
vercel.json
package.json
assets/style.css
assets/app.js
assets/admin.js
assets/sky.webp            фон первого экрана
api/_lib.js                общее: хранилище, лимиты, подписи, цены
api/_render.js             сборка HTML сайта клиента
api/generate.js            единственный файл, который ходит к модели
api/terms.js               расписка о согласии
api/order.js               бронь суммы: первый платёж и продление
api/claim.js               клиент присылает данные чека
api/status.js              статус заказа, срок размещения, цена продления
api/admin.js               панель: подтвердить, продлить, приостановить
api/draft.js               возврат к собранному сайту без повторной сборки
api/download.js            выдача файла сайта
api/site.js                показ размещённого сайта по адресу
api/contacts.js            телефон поддержки и цены для главной
api/health.js              самопроверка настроек
primery/primer-1-barbershop.html
primery/primer-2-kofeynya.html
primery/primer-3-avtoservis.html
primery/primer-4-manikyur.html
```

Папку `primery` заливать **обязательно**: на главной есть блок «Примеры»,
он показывает эти файлы. Без них там будут пустые окна.

Папки `assets` и `api` создаются так: **Add file → Create new file** и в имени
пишете `api/_lib.js` — GitHub сам сделает папку. Дальше содержимое можно
вставлять копипастой.

## 2. Подключите хранилище

Без него заказы пропадут при первом же засыпании сервера.

Vercel → ваш проект → **Storage** → **Upstash Redis** → Create.
Vercel сам добавит переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN`.
Ничего вручную вписывать не надо.

## 3. Добавьте переменные окружения

Vercel → Settings → **Environment Variables**. Ставьте на все среды
(Production, Preview, Development).

| Имя | Обязательна | Что писать |
|---|---|---|
| `ADMIN_PASSWORD` | да | Пароль от панели. Длинный, не «12345». |
| `ADMIN_SECRET` | да | Любая случайная строка символов на 40+. Ею подписываются входы в панель и расписки о согласии. |
| `ANTHROPIC_API_KEY` | да* | Ключ модели. |
| `OPENAI_API_KEY` | да* | Альтернатива предыдущему. |
| `SUPPORT_WHATSAPP` | **да** | Ваш номер для связи, например `+7 707 123 45 67`. Без него блок помощи скажет, что контакты не настроены |
| `SITE_DOMAIN` | нет | Ваш домен для сайтов клиентов, например `wedesign.site`. Тогда сайт клиента открывается как `barber-loft.wedesign.site`. Не задан — работает запасной адрес вида `ваш-проект.vercel.app/s/barber-loft` |
| `SUPPORT_PHONE` | нет | Если для звонков другой номер |
| `SUPPORT_EMAIL` | нет | Почта, если есть |
| `SUPPORT_HOURS` | нет | Когда отвечаете, например `с 10:00 до 20:00` |
| `KASPI_URL` | нет | По умолчанию `https://pay.kaspi.kz/pay/cwevqlzj` |
| `PRICE_SITE` | нет | Первый платёж: сайт плюс первый месяц. По умолчанию `9990` |
| `PRICE_RENEW` | нет | Продление за месяц. По умолчанию `4990` |
| `PERIOD_DAYS` | нет | Сколько дней размещения даёт один платёж. По умолчанию `30` |
| `AI_MODEL` | нет | Если хотите другую модель. По умолчанию `claude-sonnet-5` |
| `LIMIT_PER_IP_DAY` | нет | Бесплатных сборок с устройства в сутки, по умолчанию `4` |
| `LIMIT_GLOBAL_DAY` | нет | Потолок сборок на весь сайт в сутки, по умолчанию `250` |
| `PAY_WINDOW_MIN` | нет | Сколько минут держится бронь суммы, по умолчанию `90` |

Раньше цена задавалась переменной `PRICE_KZT` — её больше нет. Если она
осталась в настройках Vercel, удалите: цену теперь берут `PRICE_SITE` и
`PRICE_RENEW`, а старая переменная просто молча не действует.

\* нужен один из двух.

**Ключ модели вводится только здесь.** В файлах проекта его нет ни в одном
месте — искать бесполезно, и из браузера его не достать.

После добавления переменных нажмите **Redeploy**, иначе они не подхватятся.

## 4. Проверьте, что всё встало

1. Откройте главную, заполните форму, нажмите «Собрать сайт» — должен появиться
   предпросмотр с водяным знаком.
2. Откройте `/admin`, войдите паролем. Сверху должно быть написано
   `хранилище: redis`. Если написано «память» — вернитесь к шагу 2.
3. Нажмите «Собрать сайт» пять раз подряд — на пятый должно прийти
   «Сегодня бесплатных генераций больше нет». Значит лимит работает.
4. В шапке панели должно быть написано, сколько заказов ждут проверки,
   у скольких размещение истекает и у скольких истекло. Если вместо панели
   выскакивает окно с ошибкой — у вас старый `assets/admin.js`, перезалейте.
5. Проверьте продление: в панели у оплаченного заказа нажмите «Продлить на
   месяц» — срок в карточке должен уехать на 30 дней вперёд. Это же действие
   вы будете делать руками, если клиент заплатил мимо формы.

## Свой домен для сайтов клиентов

Сайт клиента всегда живёт **на вашем адресе**, не на его собственном. Как
только вы нажали «Платёж получен, опубликовать», сайт открывается сразу —
ничего настраивать клиенту не нужно и адрес он не выбирает. Имя делается из
названия дела само: «Барбершоп Лофт» → `barbershop-loft`. Если такое имя уже
занято, добавляется цифра.

Подключить клиенту его собственный домен проект не умеет. Кому нужен свой
адрес — тот скачивает файл сайта и размещает его где хочет, для этого и лежит
инструкция `fayl.html`.

Без домена сайт клиента открывается длинным адресом вида
`ваш-проект.vercel.app/s/barber-loft`. Работает, но выглядит бедно.

Со своим доменом — `barber-loft.вашдомен.site`. Чтобы так стало:

1. Купите домен и добавьте его в Vercel → Settings → Domains. Нужен ещё
   поддомен-звёздочка `*.вашдомен.site` — Vercel подскажет, какую запись
   добавить у регистратора.
2. В файле `vercel.json` замените `ВАШ-ДОМЕН` на своё имя домена. Там строка
   с `(?<sub>...)` — меняете только название, остальное не трогайте.
3. Добавьте переменную `SITE_DOMAIN` со значением `вашдомен.site`.
4. Redeploy.

Порядок важен: если поставить `SITE_DOMAIN`, а `vercel.json` не поправить,
клиент получит красивый адрес, который никуда не ведёт.

## Как проходит оплата

Оплата помесячная, но **без автосписаний**: деньги никогда не уходят сами.
Первый платёж — это сайт плюс первые 30 дней размещения. Дальше клиент
платит за каждый следующий месяц сам, когда захочет.

1. Клиент оставляет телефон для связи и жмёт «Забрать сайт». Сервер бронирует
   уникальную сумму: 9 990 + случайный хвостик, например **10 127 ₸**. Пока
   бронь жива, эту сумму не выдадут никому другому.
2. Клиент платит по вашей ссылке Kaspi ровно эту сумму.
3. Клиент вписывает имя отправителя, номер чека Kaspi и время платежа.
4. Вы открываете `/admin` → «Ждут проверки». В карточке заказа стоит готовый
   список того, что нужно сверить в приложении Kaspi. Совпало — «Платёж
   получен, опубликовать». Не совпало — «Платежа нет».

Панель сама подсвечивает подозрительное: сумма не та, чек уже был в другом
заказе, оплата после истечения брони.

Имя плательщика на входе не спрашивается специально: за человека часто платит
жена, брат или коллега, и требовать совпадения — значит краснеть панелью
без повода. Платёж опознаётся суммой, а не именем.

Автоматической выдачи нет ни в каком виде. Сайт становится публичным только
после вашего нажатия.

## Как проходит продление

Продление устроено ровно так же, как первая оплата, — та же уникальная сумма,
тот же чек, то же ваше подтверждение. Разница одна: модель не вызывается и сайт
не пересобирается, поэтому продление вам ничего не стоит.

1. Клиент открывает главную → «Проверить свой заказ» → вводит свой код
   `WD-XXXX`. Видит плашку: сколько дней осталось и сколько стоит месяц.
2. Жмёт «Продлить». Сервер бронирует новую уникальную сумму — уже от цены
   продления, например **5 123 ₸**.
3. Клиент платит и присылает чек так же, как в первый раз.
4. Вы в панели нажимаете «Платёж получен» — срок уезжает на 30 дней вперёд.

Неиспользованные дни не сгорают: если клиент продлил заранее, новый месяц
прибавляется к остатку, а не съедает его. Это прямо написано в оферте.

**Когда месяц кончился.** Сайт закрывается сам: по его адресу открывается
уведомление, что размещение закончилось. Ничего не удаляется — данные лежат
на месте, клиент платит и сайт возвращается тем же адресом.

**Что вы делаете руками.** В панели у оплаченного заказа три кнопки:

| Кнопка | Что делает |
|---|---|
| Продлить на месяц | Ставит срок на 30 дней вперёд. Нажимайте, только если платёж реально получен — панель это не проверяет |
| Приостановить | Закрывает сайт сразу. Заказ и данные остаются, клиент может продлить и вернуть его |
| Отозвать | Снимает сайт с публикации совсем и закрывает скачивание файла. Уже скачанный клиентом файл это не отменяет |

Фильтры в панели «Истекают» и «Истекли» показывают, кому пора платить.
Рядом с такой карточкой есть кнопка «Напомнить о продлении» — она открывает
WhatsApp с готовым текстом и кодом заказа.

**Напоминаний сервер не рассылает.** Ни писем, ни SMS: почтовой рассылки в
проекте нет. Раз в неделю заходите в панель и смотрите фильтр «Истекают» —
это и есть вся работа по продлениям.

## Самопроверка

Если что-то не запускается, откройте в браузере:

```
https://ваш-адрес.vercel.app/api/health?key=ВАШ_ADMIN_PASSWORD
```

Страница покажет: какие переменные окружения сервер реально видит (только
имена, без значений), правильно ли выглядит адрес хранилища, есть ли в токене
лишние пробелы, и результат живой попытки записи в Upstash с точным кодом
ошибки. Секреты она не выводит никогда.

Пароль попадёт в логи Vercel как часть адреса — после отладки его лучше
сменить.

## Если что-то не работает

Откройте Vercel → Deployments → верхний деплой → **Logs**, повторите действие
на сайте и посмотрите строку с `[wedesign]`.

| Сообщение на сайте | Что делать |
|---|---|
| Хранилище отклонило запрос (403 или 401) | В `KV_REST_API_TOKEN` лежит read-only токен. Возьмите основной в панели Upstash → REST API. Затем Redeploy |
| Хранилище не найдено (404) | `KV_REST_API_URL` должен начинаться на `https://` и заканчиваться на `upstash.io`, а не `redis://` |
| Сервер не нашёл /api | Папка `api` лежит не в корне репозитория. Либо перезалейте, либо укажите Root Directory в настройках Vercel |
| На сервере не настроен ключ ИИ | Не задан `ANTHROPIC_API_KEY` (или `OPENAI_API_KEY`). После добавления — Redeploy |

Любая переменная подхватывается только после Redeploy. Это причина примерно
половины «ничего не изменилось».

## Перед первой продажей — обязательно

Код готов, но продавать без этого нельзя:

0. **Обновляйте версию согласия при правке оферты.** В `assets/app.js` есть
   строка `var TERMS = '2026-08-01';`. Поменяли текст оферты — поставьте новую
   дату, и у всех согласие спросят заново. Иначе клиент, принявший старую
   редакцию, будет считаться принявшим новую, а это не так.

1. **Заполните `oferta.html` и `politika.html`.** Там подчёркнутые пропуски —
   ваше наименование, адрес, телефон, сроки. Без реквизитов оферта
   юридически пустая.
2. **Заполните реквизиты в подвале `index.html`** — ищите комментарий
   «ЗАПОЛНИТЬ».
3. **Оформите ИП или ТОО**, если ещё нет. Приём платежей на личную карту от
   регулярной предпринимательской деятельности — отдельный риск.
4. **Проверьте у юриста вопрос хранения данных.** Законодательство Республики
   Казахстан содержит требования к месту хранения персональных данных граждан.
   Vercel и Upstash находятся за пределами РК. Я не юрист и не могу сказать,
   как это применяется к вашему случаю — спросите специалиста.
5. **Решите, что делать с чужими товарными знаками.** Клиент может вписать
   чужое название. Ответственность на нём по оферте, но проверять сайты перед
   публикацией всё равно ваша задача.

## Как доказать согласие клиента

Клиент нажал галочку → сервер выписал расписку `ACC-XXXXXXXX` и сохранил:
своё время (не с часов клиента), редакцию документов, сетевой адрес и
отпечаток устройства. Запись подписана ключом `ADMIN_SECRET` — правка любого
поля ломает подпись.

В карточке заказа панель показывает номер расписки, дату и надпись
«не зафиксировано», если согласия нет.

**Где смотреть.** Никаких писем не приходит — всё лежит в базе. Два места:

1. **В карточке заказа** — строка «Согласие с условиями» с датой и номером
   расписки, рядом кнопка «Расписка о согласии».
2. **Вверху панели** — поле «Проверить расписку о согласии». Введите номер
   `ACC-XXXXXXXX` (его называет клиент) и получите полную таблицу: что принято,
   когда, с какого адреса, с какого устройства, плюс вердикт о подписи.

Таблицу можно распечатать или сохранить в PDF через печать страницы — это и
будет ваш документ для спора.

**Важно:** не меняйте `ADMIN_SECRET` после начала продаж. Он подписывает
расписки — со сменой ключа все прежние перестанут проверяться.

## Как клиент с вами свяжется

Номер задаётся **один раз** переменной `SUPPORT_WHATSAPP` и подставляется сразу
везде: в блок «Помощь», в зелёную кнопку в углу экрана, в сообщение об
отклонённом платеже и в подпись под готовым сайтом. Менять номер в разметке
не нужно.

В сообщение WhatsApp автоматически подставляется код заказа клиента — вам не
придётся его выспрашивать.

## Кто стоит за заказом

Регистрации в сервисе нет — значит и «личного кабинета с паспортом» нет.
Что чем является на самом деле:

| Что | Что доказывает | Насколько крепко |
|---|---|---|
| Расписка `ACC-…` | в это время с этого адреса кто-то принял условия | средне: место и время, но не имя |
| Телефон при заказе | ничего | слабо: не подтверждён, вписать можно любой |
| Отпечаток устройства | согласие, заказ и чек шли с одного места | средне: подтверждает, что действовал один человек |
| Уникальная сумма | этот платёж относится к этому заказу | сильно: сумму не спутать |
| **Имя отправителя в Kaspi** | **кто именно заплатил** | **сильнее всего: человека опознал банк, не вы** |

Вывод: настоящая идентификация приходит из банка. Всё остальное —
вспомогательные привязки, которые сцепляют платёж с заказом и согласием.

В карточке заказа панель показывает это блоком «Кто стоит за заказом» и
отдельно предупреждает, если согласие, заказ и чек пришли с разных устройств.

## Что проверено

| Что | Результат |
|---|---|
| Ключ ИИ в браузере | отсутствует, живёт только в переменных Vercel |
| Подделка токена админа | отбита (своя подпись, чужой секрет, просроченный, «вечный») |
| Подбор пароля | блокировка на 15 минут после 5 попыток |
| Внедрение кода через поля | все 10 первых экранов чистые |
| `javascript:` в ссылках | закрыто, проверяется каждый адрес |
| Трата денег впустую | 10 попыток подряд → 2 вызова модели; мусорные запросы → 0 вызовов |
| Дубль чека | помечается автоматически |
| Заниженная сумма | помечается автоматически |
| Утечка в статусе заказа | телефон и данные чека клиенту не отдаются |
| Снятие с публикации | сайт сразу отдаёт 404 |

## Что где лежит

- `api/generate.js` — единственный файл, который ходит к модели. Здесь же три
  уровня лимитов: 2 сборки в минуту с устройства, 4 в сутки с устройства и
  общий суточный потолок на весь сайт.
- `api/_render.js` — сборка HTML сайта. **Верстает только сервер**: браузер
  клиента не может прислать свой HTML, потому что HTML у него никто не спрашивает.
- `api/draft.js` — возврат к уже собранному сайту. Модель тут не вызывается:
  человек закрыл вкладку и вернулся — платить второй раз не за что. Черновик
  живёт 30 дней.
- `api/admin.js` — панель. Пароль сверяется побайтово, вход выдаёт подписанный
  токен на 8 часов, 5 неудачных попыток подряд блокируют вход на 15 минут.
  Здесь же продление, приостановка и отзыв сайта.
- `api/order.js` — бронь уникальной суммы. Один и тот же файл обслуживает
  первый платёж и продление: во втором случае приходит код заказа вместо
  черновика, поэтому сайт не пересобирается.
- `api/site.js` — отдаёт размещённый сайт по адресу. Он же показывает
  уведомление вместо сайта, когда оплаченный срок вышел.
**Описание не обязательно.** Достаточно либо описания дела, либо списка услуг.
Без описания модель получает прямой запрет выдумывать: блок «о нас», цифры и
порядок работы просто не появляются, сайт собирается короткий — первый экран,
услуги, часы, контакты. С описанием страница становится полной.

**Пожелания по цвету.** В форме есть поле «Пожелания по виду сайта». Если
владелец написал «в розово-красных цветах» или «тёмный премиальный» — палитра
выбирается только из подходящих. Слова ищутся и в самом описании бизнеса.
Распознаются: розовый, красный, оранжевый, синий, зелёный, фиолетовый, жёлтый,
тёмный, светлый, монохром. Отрицания («не розовый») учитываются. По сфере
деятельности цвет не угадывается — это решает владелец.

- `api/_render.js` → `makeDNA()` — та самая «ДНК дизайна»: 18 палитр, 14 пар
  шрифтов, 8 типов первого экрана, 5 характеров движения, включая появление заголовка по словам, 5 скруглений, 3 меню,
  зерно и mesh-градиенты по жребию, **объёмный слой** (парящий шар, лента в
  перспективе, уходящая сетка), наклон карточек за курсором, параллакс,
  случайный порядок 7 блоков — **плюс разные раскладки внутри блоков**: услуги четырьмя способами (карточки, строки,
  нумерация, прайс-лист), «о нас» четырьмя (сплит, центр, цитата, широкий),
  часы тремя (таблица, сетка, строки). Меняется не только цвет, но и устройство
  страницы. Каждая выпавшая комбинация записывается в базу и повторно не выпадет.

## Что этот проект пока НЕ делает

Чтобы не обещать лишнего клиентам:

- нет загрузки файлов: фотографии добавляются ссылкой (https), иначе в галерее
  будут градиентные блоки в цвет сайта;
- нет личного кабинета и регистрации, только код заказа `WD-XXXX`;
- нет автосписаний: размещение помесячное, но каждый платёж клиент делает сам.
  Не заплатил — сайт просто закрывается, деньги ниоткуда не спишутся;
- нет напоминаний по почте и SMS: о продлении вы пишете сами из панели.
